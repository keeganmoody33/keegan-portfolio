# Lessons Learned

Updated: 2026-10-07

## Collection research match-quality gates (2026-10-07)

- **MusicBrainz 429s never burn `CRATE_MAX_ATTEMPTS`.** `countsTowardAttempts` is false for `auth` and `rate_limit`. Five-plus consecutive MB 429s must not mark an id dead.
- **MusicBrainz and Discogs 429s stop the backfill walk.** `shouldStopWalkOnRateLimit` keys off `MUSICBRAINZ_RATE_LIMIT_MESSAGE` or `DISCOGS_RATE_LIMIT_MESSAGE`. Wikidata 429 is `rate_limit` too — keep walking. Pause only for Retry-After (seconds or HTTP-date via `readRetryAfterMs(..., nowMs)`). Cap MusicBrainz Retry-After at `MUSICBRAINZ_RETRY_AFTER_CAP_MS` (120s).
- **SPARQL and MusicBrainz abort timers are `min(timeout, deadline remaining)`.** If remaining is 0, throw timeout without fetching. Do not inject a default Wikidata client in queue/backfill or `NODE_TEST_CONTEXT` tests hit live SPARQL with a mismatched `now()`.
- **Track-level samples pick one recording.** Strip `feat.` / `ft.` / `featuring` from artist and title. Reject a hit whose duration is more than `DURATION_FAR_MS` (15s) off when both durations are known. `TRACK_LEVEL_FETCH_CAP` is 1. Do not merge sample rels from far-off recordings.
- **Samples are MusicBrainz `samples material` on recordings or releases, matched by type-id.** Recording-recording `9efd9ce9-e702-448b-8e76-641515e8fe62`, recording-release `967746f9-9d79-456c-9d1e-50116f0b27fc`. Direction comes from the relation `direction` field (`forward` → `sample_of`, `backward` → `sampled_by`). The reverse-phrase label `sampled by` is not a separate type and must not invert. Work-to-work (`based on`, parody, arrangement, medley, translation, other version) is not a sample — do not fetch MusicBrainz `/work/` or store a `musicbrainz.org/work/` `sourceUrl`. Read-time filters (`isRecordingOrReleaseSampleLink` and `factsFromRecordings`) drop only those MusicBrainz work URLs. Wikidata P5707 facts use `wikidata.org/wiki/Q*` — keep them through merge, hydrate, persist, coverage (`withReleaseSamples`), and render.
- **`applyDeadlineStop` must copy `trackSampleCursor`.** Dropping it re-searches from track 0. `persistTrackLevelDocs` attaches/merges first, then `setRecording` (clone) so Redis has the merged samples.
- **Enrich lock TTL is 90s; re-entry is in-process only.** `SET NX` plus Lua compare-and-extend with the same token. Cron / keep / CLI always pick a fresh UUID via `selectEnrichLockToken` — never read or write `crate:enrich:meta:v1`. A saved token with no TTL made every worker share one UUID, so the second could step into the first lock and its release deleted it. Lua compares the raw GET value; do not strip JSON quotes (`"X"` must not match `X`). Discogs release fetch timeout (`DISCOGS_RELEASE_TIMEOUT_MS` 15s) stays armed through `response.json()` and well under the 90s lock TTL. Do not use a 3700s lock TTL.
- **Official `npm run crate:backfill` is one 45s tick.** `--ids=a,b,c,d --retry` still stops at the take floor. A 20-track rematch (Kiss 5150579) burned the whole budget; the other listed ids never started. Do not loop the official CLI unless asked.
- **Bare `--retry` must scan stored pressings, not only dead ∪ inspect.** A pressing can have `lastError` `rate_limit` and provenance still `pending` while missing from inspect (1323531). `retryBackfillTargets(store, collectionIds)` includes those retryable lastError kinds.
- **Sample relations often omit nested `artist-credit`.** Fill `relatedArtist` from a follow-up recording or release artist-credit lookup. Skip MusicBrainz work URLs only. If it still cannot be resolved, render the title only — no empty ` — ` artist slot.
- **A 429 overlay must not double sample rows.** `overlayTrackLevelProgress` keeps stored `researchFacts` and swaps in fresh recordings. Dedupe sample facts on `kind + trackKey + sourceId` (not artist) and keep the row that has an artist. Same for `mergeSampleLinks` on `mbid`.
- **MusicBrainz `[unknown]` is not a name.** Artist id `125ec42a-7229-4250-afc5-e057484327fe` and the literal `[unknown]` are empty in `artistCreditName` and artist fill. Drop the joinphrase of the part before a removed `[unknown]` (`Alpha & [unknown]` → `Alpha`, not `Alpha & `). Rows show the title only — never `Unknown` or a stray dash.
- **OVERVIEW connection title links need the same 24px target as FactSampleList.** `inline-flex min-h-6 items-center`, not `inline-block` (20px text). Keep `mt-1` under the label. WCAG 2.5.8. Long titles also need `[overflow-wrap:anywhere] min-w-0 max-w-full` or the page overflows at 320/375 (WCAG 1.4.10).
- **Keep a prior match's `releaseGroupMbid` undefined until that release is queried.** Do not copy `null` from a weaker unmatched refresh with a different MBID; skip-match would skip the P436 backfill.
- **Overlay a checkpoint-only cursor without replacing committed tracks.** `trackSampleCursor: 0` is a real cursor. Early-return must not drop it; applying overlay tracks with no recording docs must not clobber the committed association.
- **Keegan accepted song-level / mix-version track matches** (How High Remix, Murder Rap instrumental, Mtume instrumental inheriting Juicy). Do not reject those as false positives.

## Credits vs samples (2026-10-07)

- **Credits can come from Discogs extraartists and Wikidata; sample-of / sampled-by cannot.** Full preview backfill of 276 ids: credits on 255 Discogs / 135 Wikidata / 144 MusicBrainz records; sample facts on 95 records, all MusicBrainz (Discogs 0, Wikidata 0). Mtume → Biggie Juicy is a MusicBrainz recording relationship. Skipping MusicBrainz to dodge 429s drops that graph. No WhoSampled, no scraping.
- **After waiting out a global MusicBrainz 429, defer that id and walk other remaining ids.** Stalling on one fat album (Kiss Alive II 5150579) burns the cooldown and never drains the rest. `shouldStopWalkOnRateLimit` still stops the current tick; the next tick should not lead with the same cooling id.
- **Do not invent coverage.** A Cloud Agent VM with no `KV_REST_API_*` / `UPSTASH_REDIS_REST_*` cannot run `npm run crate:backfill`. Skip and say so. Do not decrypt Vercel Production env. Do not write unprefixed `lf:` keys. Upstash MCP `redis_list_databases` returning `[]` is also a skip. This VM did have preview Redis; artifact is `/opt/cursor/artifacts/preview-full-backfill.json`.

## Footer request tally (2026-10-07)

- **Bar colors are house tokens, not invented greys.** `#1a1a1a` / `#4a4a4a` are not decided colors and fail in light theme. Track `--house-line`, fill `--house-ink` / `--house-dim`. LCD may keep `--house-lcd` / `--house-lcd-ink`. Fonts are the existing `--house-font-*` tokens (Doto / Roboto Mono / Space Grotesk). LCD has no radius.
- **Focus is 2px solid ink, not orange `outline: auto`.** Orange is hover only (`FRONTEND_GUIDELINES` house-text-button, `globals.css` `.house-text-button:focus-visible`). Tailwind v3 sets solid via `outline` (`outline-style: solid`); `outline-solid` is v4 and is dropped here, so Chrome keeps `outline: auto` (rounded ring, reads as orange). Use `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-[var(--house-ink)]`.
- **`recordHit` is one Upstash pipeline.** `hincrby` then `setnx` as separate REST calls is two round trips. Pipeline them. Stay inside `event.waitUntil`, never throw, never delay the response — bots and AI crawlers must not be slowed. Resolve `redis()` *inside* the try: default-arg evaluation runs before the body and a config throw would escape.
- **Do not import `discogs-store` from Edge.** `proxy.ts` → `tally-store` pulling `discogs-store` put ~273K on the middleware chunk. Redis REST config and `discogsKeyPrefix` live in `lib/redis-env.ts` (no Discogs/crate/SDK). Crate paths keep importing the re-exports from `discogs-store`.
- **Production Redis is `VERCEL_ENV=production` *and* ref `main`.** Same `isProductionRedisNamespace` as Discogs. `vercel --prod` from another branch must write `lf:preview:tally:v1`, not `lf:tally:v1`. Visitor writes stay `*:tally:v1` / `*:tally:v1:since`.
- **Do not paint a loading chip that later unmounts.** That is CLS. Reserve the collapsed-row height from first paint; keep content `invisible` + `inert` until `/api/tally` 200. Errors keep the reservation.
- **Hover/focus must not select a category.** Selection is click / Enter / Space. Disclosure name is the visible `breakdown` / `close` (chip is not in the button). Humans / not humans: visible label = accessible name, `aria-pressed`. Honor `prefers-reduced-motion` (`motion-reduce:transition-none motion-reduce:duration-0`). Breakdown tap target is `min-h-11` / `sm:min-h-8`.
- **`cache: 'no-store'` on the footer fetch fights `s-maxage=60`.** Drop it so the CDN cache applies. 503s get a short `s-maxage=10`. `readTally` times out around 1.5s.
- **Preview Redis stays `lf:preview:tally:v1`.** Production is `lf:tally:v1`. Do not write prod Redis from a preview or this environment. No `vercel.json` crons.

## Dependabot grouped npm bumps (2026-10-07)

- **A grouped `npm_and_yarn` PR can jump Tailwind majors via caret ranges.** #52 claimed `source-map-js` 1.2.1 → 1.2.2 (CVE-2026-93749) and removing `postcss-selector-parser`, but it also changed `tailwindcss` `^3.3.0` → `^4.3.3`. That breaks the Vercel/Turbopack build (`tailwindcss used directly as PostCSS plugin`). `portfolio-site/` is the Vercel `rootDirectory` — do not merge a Tailwind v4 jump.
- **Patch `source-map-js` in the lockfile only.** It is transitive via `postcss@8.5.23` (`^1.2.1`). `npm update source-map-js` is enough; no `overrides` and no `package.json` change. Keep Tailwind v3. `postcss-selector-parser` is a Tailwind v3 dependency — leaving it is correct.

## Collection covers (2026-10-06)

- **Discogs API Terms forbid storing copies.** Do not put Discogs images on Vercel Blob or keep them as a long-lived object store. Hotlink `images[0].uri` / primary. Manifests may record the Discogs URL plus width/height. Cover Art Archive may be copied at our own risk; images stay copyrighted. No extra CAA notice on the page — keep existing Discogs credits.
- **Missing `BLOB_READ_WRITE_TOKEN` must no-op.** Discovery still runs. CAA-best manifests get `url: ''` and `stored: false`; `displayCoverUrl` falls back to the Discogs listing/cover. Do not throw from the visitor path.
- **`covers:sync` refuses prod Redis** unless `--prod`. Preview keys stay `lf:preview:crate:cover:{id}:v1`. Never write production `lf:` from this script by accident.
- **`lecturesfrom-covers` auto-link set Production.** The store was already connected to Preview, Development, and Production. Do not add a second Production token. Connecting a Blob store injects `BLOB_READ_WRITE_TOKEN` on every selected environment.
- **Unauthenticated Discogs is 25/min.** Cover sync without `DISCOGS_TOKEN` must use 2.5s, not 1.1s, or a full-collection run 429s. Authenticated stays 1.1s.
- **Client components cannot import `cover.ts`.** It pulls `node:crypto` and Discogs fetch. Import types and `displayCoverUrl` from `cover-display.ts`. Discogs `next/image` URLs stay `unoptimized` so the optimizer does not 403 the CDN.
- **Grid hotlink is `thumbnail` then `cover`.** `discogsGridHotlink` prefers the listing thumb unless a stored CAA Blob URL exists. `next/image` always gets `sizes`. SampleList title links keep `#53` `inline-flex min-h-6 items-center`. Detail blur placeholder uses `motion-reduce:blur-none`. A broken image falls back to the empty square / `NoArtTile`.

## Collection research: manual-only, fallbacks, hardening (2026-10-06)

- **A visit never writes Redis.** No `after()` enqueue, no `keepCollectionFresh` on `/collection`, no `vercel.json` cron. Visitors read stored data, a fixture, or the pending shell. `too_slow` used to come back on the next listed visit; with visit enqueue gone, recovery is only a manual `--retry`.
- **Research is gated.** `GET /api/cron/crate-backfill?ids=567894&retry=1` and `npm run crate:backfill -- --ids=567894 --retry`. `CRON_SECRET` is not in production. Missing secret → 404. Do not add it without Keegan's yes.
- **Fallback order is MusicBrainz → Discogs extraartists → Wikidata.** Wikidata identity is Discogs master `P1954`, then MusicBrainz release group `P436`, then Discogs release `P2206` / MusicBrainz release `P5813` (`mbRelease.mbid`, not catalog/catno). More than one item is ambiguous — do not merge. Samples are `P5707` inbound/outbound (P736 is cover art by; P144/P4969 are adaptations). Track-level samples are the primary path: artist + song title (mix suffixes and `feat.` / `ft.` / `featuring` stripped), pick the closest duration-ok recording (`DURATION_FAR_MS` 15s reject; `TRACK_LEVEL_FETCH_CAP` 1). MusicBrainz sample rels are `samples material` / `sampled by` only — not `based on`. Normalize to one schema with source + source id/url + fetchedAt. Persist `creditLine(credit)` (attributes + role) on research facts so `assistant engineer` does not collapse to `engineer`. Dedupe by normalized role synonyms (`composer` / `composed by` → written by); drop a release-level credit when the same person+role is already track-attributed. Track coverage counts only track-attributed facts; release-level coverage is separate. No WhoSampled, no scraping. One shared Wikidata client (User-Agent + 1.1s + timeout + Retry-After). `lookupWikidataReleaseFacts` must not `createWikidataClient` per call — always `getSharedWikidataClient()`; tests `resetSharedWikidataClient(options)`. Injected `wikidataClient` must run even under `NODE_TEST_CONTEXT`. 429/5xx/timeout keep prior Wikidata facts, set a short `refreshAfter` (`AUTH_RETRY_MS` floor), and do not move `research.verifiedAt`. Retry-After sleep sits outside the 5s SPARQL timer (`min(5s, remaining)`) and is skipped when it would miss the worker deadline. `sourceUrl` is the claim-bearing item.
- **Drafts expire.** `setDraftPressing` SET EX 900s. Reuse only visitor-facts drafts from the current cycle (`draft.lastAttemptAt` newer than committed). `too_slow` / `drop` discard the draft.
- **Floor math is one helper.** `remainingBelowTakeFloor` is `remaining <= 0 || remaining < takeFloor`. After `takeDue`, re-check the floor and nack without a deadline stop if remaining dropped (the take is async). After `getPressing` in backfill, re-check again before enriching. `enrichPressing` still re-checks at entry as a safety net. Proof drains use `ENRICH_BUDGET_MS` (45s), not 8s. A missing backfill `settled` array is `[]`, not `ids.slice(0, cursor)`. `--retry` without ids retries dead, inspect `too_slow` / `rate_limit` / `unavailable`, and stored pressings whose lastError is still retryable (including pending provenance). Success must `unmarkUnresolved` so `--retry` does not keep force-refreshing finished records. Persist `releaseGroupMbid` (including `null` after a lookup); only `undefined` means the field was never stored and skipMatch may `getRelease` without rematching. `keepPriorMatch` inherits a group from `next` only when the retained release IDs agree; otherwise leave `undefined` so skip-match can still query. `preservePressingOnFailure` / `withClearedDeadlineStops` / `applyDeadlineStop` must copy `trackSampleCursor` or skipMatch re-runs recording search.

## Collection record detail (2026-10-06)

- **Exhausted or terminal-unmatched must rematch on retry.** `skipMatch` is not just `matchStatus !== pending`. Exhausted preserve sets `unmatched`, so a dead `{ retry: true }` used to skip MusicBrainz, clear `lastError`, and move `verifiedAt`. Rematch when `lastError` is `exhausted` or `not_found`. Mtume's genuine unmatched/ambiguous with `lastError` null still skips. `provenance.verifiedAt` moves only when MusicBrainz actually succeeds. Discogs-checked time is `lifecycles.pressing.verifiedAt`. A skip-match Discogs refresh with 0 MB calls must not bump `provenance.verifiedAt`. A first-run Discogs-ok / MusicBrainz-throw keeps Discogs facts and `lastAttemptAt` / `lastError`, and leaves `provenance.verifiedAt` null.
- **A worker deadline is not a failed attempt.** Throw `WorkerDeadlineError`, rethrow without `setPressing`, nack with `deadlineBackoffMs` (not `now()`), and stop the drain without `record()`. After `DEADLINE_STOP_LIMIT` (3) **consecutive** deadline stops, mark unresolved with reason `too slow`, drop the queue entry, and discard the draft. Reset `checkpoint.deadlineStops` to 0 on any non-deadline outcome. Do not count those stops as failed attempts. `too_slow` is unresolved+dropped, not dead. Recovery is a manual `--retry` (visit enqueue is gone). Skip the Discogs fetch when remaining budget is inside `ENRICH_TAKE_FLOOR_MS`; reuse a staged draft on a later tick that still has budget, only if it is fresher than the committed pressing and within TTL.
- **Backfill walks collection order, not the queue head.** Checkpoint a settled-id set (migrate `ids.slice(0, cursor)` from older snapshots). `remaining` is the current collection ids that are not settled and not dead (unless `{ retry: true }`); `remainingIsEstimate` is false. Nack unavailable to `refreshAfter` and continue — do not stall on the same id. A cooling MusicBrainz `rate_limit` must **stop** the walk (global 1 req/s). Wikidata 429 must not. Overlay `refreshAfter` is Retry-After (seconds or HTTP-date), not `max(Retry-After, preserve 1h backoff)`. Skip dead ids unless retry; when `isBackfillSettled` (including unmatched with `lastError` null), `ack` the queue entry and `unmarkDead` unless the outcome is `exhausted`. Auth still stops the run. Do not enqueue remaining ids into the visitor queue as a bulk dump. `estimatedRemainingMs` is the time estimate.
- **Visitor path never calls Discogs release detail, MusicBrainz, or Wikidata, and never writes Redis.** Read Redis last-good (title or tracks), then committed fixtures, then a pending shell from the collection snapshot. An empty error stub is not last-good. `{releases:[], items:0}` is not a complete last-good. Enrichment uses the fixture as previous when Redis has no visitor facts. Research is gated cron routes + `npm run crate:backfill` only. A failed refresh must not overwrite a successful pressing or bump `verifiedAt`.
- **Preserve the prior verified record, not the staging draft.** Discogs success writes a staging draft with `lifecycles.pressing.verifiedAt=now` and `provenance.verifiedAt` left at the prior MB success (or null). If MusicBrainz then throws, catch must preserve the **committed** copy whenever it has visitor facts and a `lastError` or `verifiedAt` (keep attempt counts and matched facts). Use the draft only on a true first run with no committed copy so Discogs facts survive. Do not `preserve(draft)` on rematch or attempts reset to 1 and a pending draft is exposed. Unused `commitDraftPressing` was deleted; success still `setDraftPressing` then `setPressing`. **Exception for recording-level samples:** overlay in-flight `tracks`/`recordings` (and the draft if that is all we have) onto the preserved copy via `overlayTrackLevelProgress`. A 429 after `setRecording` used to drop Juicy because `hasPriorVerifiedRecord(previous)` discarded the draft. Attach whatever recording docs were fetched before rethrowing, reuse `store.getRecording` when research is fresh, and checkpoint `trackSampleCursor` after each track. After overlay, `retryAtMs` must be `now + Retry-After`, not `max(Retry-After, preserve refreshAfter)` — preserve's first attempt is a 1h backoff and that floor made every 429 skip the id for an hour.
- **Collection 401/403 is auth, not unavailable.** `crawlFullCollection` maps those statuses to `DiscogsAuthError`. `refreshDurableCollection` records `auth` and rethrows. `/api/cron/crate-enrich` short-circuits before `processEnrichmentQueue`. Do not swallow collection auth into `DiscogsUnavailableError` or the worker keeps draining.
- **Enqueue must not revive a dead id** without `{ retry: true }`. Preview Redis keys are `lf:preview:`; a preview (or a non-`main` git ref) must never write unprefixed `lf:` keys.
- **Discogs is the pressing; MusicBrainz is the recording.** Match the MB release via Discogs URL / barcode / catno, then artist + title + year/label (unique catno or a single remaining hit). Then position+title+duration. Vocal/instrumental siblings without a unique version token stay `ambiguous`. Do not auto-accept weak matches. No WhoSampled, no scraping. Keep headings and mix titles as distinct Discogs occurrences.
- **Four lifecycles, not one 6h refresh.** Collection listing, pressing facts, recording match, and research each have their own timestamps and triggers. A Discogs refresh must not rematch or re-research when track identity is unchanged. Successful credits/samples are reused indefinitely unless `CRATE_RESEARCH_REFRESH=1` (default window six months, `CRATE_RESEARCH_REFRESH_MS`). **Prototype gap:** Discogs API Terms freshness (~6h) is not implemented. Listing last-good is Redis; gated `/api/cron/collection-keep` refreshes when older than `DISCOGS_SNAPSHOT_TTL_MS` (24h). ISR is 300s. Visitors never write. No Vercel cron. Do not pretend the 6h clause is satisfied.
- **LF Direction empty copy is the whole empty language.** Missing field drops the row. Empty section: `nothing on file yet`. No track: `pick a track for credits and samples`. Checked, no match: `{reason} · checked YYYY-MM-DD` (lowercase, no hedging; date from `verifiedAt`, not a failed attempt). Store down: **only** `couldn't reach discogs` plus retry — fill the h1 from catno or id, put that catno in the `#242424` square, and do not render tabs or empty sections. Never `N/A`, `Unknown`, a dash, or a red error. No spinners or shimmer — hold the hairlines and fade (`.house-fade` = `houseLockup`).
- **Orange is hover only** on this surface. Active tab is ink + 1px ink underline. Cover is flat 1:1, same thumbnail as the grid, **1px `#242424` frame** (LF Direction overruled the no-frame pass). Title keeps Discogs casing. Missing-cover catno is `--house-ink` `#ececec` (13.1:1 on `#242424`), not dim `#7a7a7a` (3.62:1). Long tokens use `overflow-wrap: anywhere` on the h1, artist, fact values, and placeholder catno.
- **Source lines are `.house-source`.** Lowercase, 0.16em, dim, `min-h-6` hit target. Do **not** collapse the Discogs pair: lowercase `discogs` plus exact-case `.house-credit` `Data provided by Discogs.` (no `text-transform: lowercase`, no `nofollow`, link the pressing URL). `/collection` repeats the credit on the `{n} releases` line **and** at the bottom of the grid, both to the lecturesfrom collection page. Section labels stay uppercase `.house-meta` in `@layer components` so active-tab ink utilities win; `[aria-selected=true]` is ink. Description inherits Space Grotesk — drop `font-sans`. Overlay close restores `#crate-cover-{id}` after `inert` is cleared, or `#crate-pull-one` when pull one opened the overlay (`lf:collection:focus` stores the DOM id). First Escape clears a selected track; overlay second Escape/`collection` is `router.back()`. Page mode Escape and close always `push('/collection')`, then focus `main#house-content` (`tabIndex={-1}`; `#house-content:focus-visible { outline: none }` — the 2px ink ring cut a line under the header at 375; house hairline is 1px `#242424`). Overlay-only autofocus. While the overlay is open, `.house-skip` is in the inert set with the grid, header, and footer. Grid cover `alt=""`; detail cover keeps the name. Both tab panels stay mounted (`hidden` + `tabIndex={0}`) with the house 2px ink focus outline. Selected track title is ink and the extras `h2`. Track rows `aria-expanded` / `aria-controls` (no `aria-pressed`). HouseShell skip-to-content (`.house-skip`) is hidden until focused. Cover max 480px until 1280. Overlay record detail does not use `.house-fade` so dim meta starts at full opacity; page mode `.house-fade` still rests at opacity 1. Leave the 150px thumb as the detail blur placeholder only; full-res comes from the cover manifest or the Discogs primary URL.
- **Pending / unmatched after a check is not `nothing on file yet`.** Pending (not yet enriched) still uses `nothing on file yet`. After a MusicBrainz check with no pressing match, show `{reason} · checked YYYY-MM-DD`. Unmatched may still show Discogs and Wikidata credit and sample facts with source labels under that line — do not gate facts until matched (Mtume extraartists fallback). If there are no such facts, do not follow the reason line with empty credits/samples blocks.
- **No Vercel cron.** `vercel.json` has no `crons` array. The ISR `/collection` grid must not call Redis `no-store` inside `after()` (Next 16 `DYNAMIC_SERVER_USAGE`). Durable listing GETs use `next: { revalidate: 300 }`. Listing refresh and research are CRON_SECRET-gated; visitors never ping keep. `CRON_SECRET` is not in production. Lock and inflight TTLs are 90s, above the 60s worker hold. Visitor detail reads may revalidate 60s (`getPressingCached`). Worker/proof `getPressing` is `writeRedis` `no-store`. Unlisted `/collection/<n>` 404s with no Discogs, MusicBrainz, Wikidata, or Redis writes. Explicit backfill (`/api/cron/crate-backfill?ids=&retry=1`) is the research trigger. Fixtures keep the three proof records working on a preview without Redis. Do not change paid cron plans.
- **Queue is a Redis zset + dedupe set.** Take sets inflight; ack/drop removes only after a successful commit; nack rescores with backoff and must `SADD` the queued set. `ENQUEUE` front must not reset an existing score or pull a backed-off item forward, and must not revive `dead` without `{ retry: true }`. Lock is a random token with compare-and-delete Lua, TTL 90s. Exhausted items go to `lf:crate:dead:v1`; 401/403 are `auth`, stop the run, do not increment attempts, and nack `AUTH_RETRY_MS` (15 minutes) so the item resumes after the token is fixed — not `TERMINAL_REFRESH_MS` (30d). Collection-path 401/403 must throw `DiscogsAuthError` and short-circuit crate-enrich before the queue drain. Live overlap `processEnrichmentQueue` proves lock exclusion only; concurrent `takeDue` proves inflight SET NX. Exhausted-to-dead must go through the queue worker including an MB-stage failure (Discogs ok). Identity 401 is classified in `discogs-release.ts` (`errorForDiscogsStatus` / `probeDiscogsIdentity`). Live proofs for kill/recover must let the inflight TTL lapse (do not `clearInflight` the proof id). Resync with 0 MB must use the real MusicBrainz client’s `requestCount`. Proof ids 8/9 are preview-only; `/api/cron/crate-proof` refuses in production. Redis `TAKE_LUA` inflight keys must use the same `:v1` suffix as `clearInflight` / ack / nack. Preview writes go through `assertPrefixedRedisKey` (`lf:preview:`). `enrichPressing` checks the shared worker deadline before match and each recording lookup so one release cannot overrun the tick.
- **Shuffle is client-only.** Fisher-Yates the whole `/collection` grid in the browser. Do not persist the order. Reload is the ISR listing. Do not add a server shuffle or a Discogs re-fetch. Announce `shuffled` on a polite `aria-live` region and leave focus on the button. No reflow animation (reduced motion or not). Hide shuffle without JS. **Pull one** navigates a listed `releaseId` through the existing overlay so Escape restores `#crate-pull-one`. Without JS it is a link to one id picked at ISR render. ## Patterns

- API proxy pattern: browser → Next.js route handler (keeps keys server-side) → external API. All new API integrations follow this pattern.
- All components are 'use client' and live in portfolio-site/components/.
- PostHog tracking is added to every API route and interactive component.

- **Use `useId()` for DOM ids that must be stable across SSR and hydration.** `YouTubePlayer` originally generated the hidden iframe container id with `Math.random()`, which produced a different server/client `id` and caused a hydration warning even though playback still worked.

That left play/link controls focusable behind `aria-hidden` (axe `aria-hidden-focus`). Pair `aria-hidden` with `inert` on every inactive or hidden panel; drop `inert` when the panel is active. After a skip, deadline is `now + 10s`; the first BUFFERING/CUED/new id extends to a hard cap of `errorTime + 25s`; later signals do not move that cap. ## Component Architecture

- **Never gate a `<Script>` tag behind loading state that the script itself resolves.** The YouTubePlayer had `<Script src="youtube.com/iframe_api">` inside the "ready" return path, but `isLoading` was only set to `false` by the `onReady` callback — which required the script to have loaded. Classic deadlock on cold loads. It only worked in dev because hot-reload kept `window.YT.Player` alive from the previous render. Fix: always render the `<Script>` and hidden iframe, use a ternary for the skeleton vs. controls below them.
- **Don't read React state from callbacks that fire synchronously after `setState`.** `persistState` captured `playing` from its `useCallback` closure, then `onStateChange` called `setPlaying(true)` and immediately `persistState()`. The closure still held the old value because `setState` is async. Fix: read the authoritative value from the source-of-truth API (`player.getPlayerState()`) instead of React state. This also removes the state variable from the dependency array, making the callback a stable reference.
- **Banner widgets should be single-row, inline-label layouts.** The original RecentDigs used `flex-1 aspect-square` covers (~250px each on desktop) with metadata text below, consuming massive vertical space. The fix: fixed-width thumbnails (72px desktop / 60px mobile), inline labels, no metadata text (title on hover). Same pattern for GitHubActivity: label + chart + push count all on one row.
- **When rotating widgets that contain iframes/scripts, keep all children mounted.** BannerRotator uses `opacity-0 absolute pointer-events-none` for inactive panels instead of `display: none` or conditional rendering. This is critical for YouTubePlayer — the hidden YouTube iframe must stay in the DOM for audio to continue playing when the panel rotates away. Using `hidden` or unmounting would kill the audio stream.
- **`YT.Player` replaces its target `<div>` with an `<iframe>`; `destroy()` removes it from the DOM entirely.** React doesn't know the element was removed (it happened outside the reconciler), so it won't re-create it. In strict mode (mount → cleanup → mount), `destroy()` in the cleanup leaves no container for the second `initPlayer()` call, causing silent failure. Fix: before calling `new YT.Player(id, ...)`, check `document.getElementById(id)` and re-create the element inside a wrapper ref if missing.

- **Set `read_only=false` in the MCP URL if you need to write SQL.** The default Supabase MCP setup URL uses `read_only=true`, which silently blocks mutations. If you're planning to run INSERT/UPDATE/DELETE via MCP, flip it before you start.

## Edge Function Deployment

- **`import { serve } from "https://deno.land/std@0.168.0/http/server.ts"` is deprecated.** Use the built-in `Deno.serve()` instead. The std/http server module was the old pattern; modern Deno has `Deno.serve` as a global. Both Edge Functions were updated 2026-07-24.
- **Pin `@supabase/supabase-js` in Edge Functions.** The original used `@2` (floating major). Pin to a patch version (e.g. `@2.90.1`) for reproducibility — matches the version in package.json.
- **`request.ip` is not in the standard `NextRequest` type.** Next.js exposes it at runtime but TypeScript doesn't know about it. Use `(request as NextRequest & { ip?: string }).ip` to access it without TS errors. The rate-limit.ts helper handles this; API routes that reference `request.ip` directly in PostHog properties need the same cast.
- **In-memory rate limiting is a stopgap for Vercel.** Each serverless instance has its own memory, so rate limits won't be accurate across multiple instances. Acceptable for a low-traffic portfolio site. For production-grade, use Upstash Redis or Vercel KV.

The first subagent pass missed references in spec docs that weren't in the original task list. A final grep caught them.
